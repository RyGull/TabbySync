Paste-ready text for the Chrome Web Store and AMO dashboards
============================================================

One file per box. Open it, select all, paste. No markdown, no code fences,
nothing to strip out first — the store's fields are plain text and render
none of it.

  01-detailed-description.txt   Store listing → Description
  02-short-description.txt      Store listing → Summary (132 char limit; this is 124)
  03-single-purpose.txt         Privacy practices → Single purpose
  04..10-permission-*.txt       Privacy practices → one box per required permission
  11-permission-notifications.txt Privacy practices → notifications permission justification
  12-permission-host.txt        Privacy practices → host permission justification (optional)
  13-whats-new.txt              Optional; some listings show it, some don't

Firefox (addons.mozilla.org) asks for four of its own:

  14-amo-privacy-policy.txt     "This add-on has a Privacy Policy" -> the box
  15-amo-reviewer-notes.txt     "Notes to Reviewer"
  16-amo-developer-comments.txt Technical Details -> Developer Comments (public)
  17-amo-whiteboard.txt         Technical Details -> Whiteboard (reviewers only)

AMO's limits, read out of its own source (addons-server) after "Notes to
Reviewer" silently swallowed everything past character 3000:

  Notes to Reviewer (approval_notes)      3000   file 15 is 2912
  Developer Comments                      3000   file 16 is 1806
  Release notes                           3000   file 13 is 809
  Summary (no URLs allowed in it)          250   file 02 is 124
  Description                            15000
  Privacy policy                        150000   file 14 is ~6455
  Whiteboard                            100000   file 17 is 1257

The two 3000s are the ones to watch: paste past them and the rest is gone
without a warning.

The privacy policy and Developer Comments fields render Markdown, which is
why file 14 has a blank line after every heading and before every list --
without them, Markdown folds a heading into the paragraph below it -- and
why file 16 uses **bold** rather than capitals. Notes to Reviewer and the
Whiteboard are plain text.

The UUID shown on that page is read-only: it is browser_specific_settings
.gecko.id from the manifest (GECKO_ID in scripts/make-manifest.mjs), and it
must never change once published, or Firefox and AMO stop recognising an
update as the same add-on.

AMO's other listing fields (name, summary, description) take the same text as
files 01 and 02. It has no per-permission justification boxes -- the data
declaration in the manifest does that job there -- and its licence picker
should be set to "All Rights Reserved", the only entry that matches LICENSE.

Two things about the description that are easy to get wrong:

* Paragraphs are single long lines on purpose. The store reflows them to
  the width of the page. Hard-wrapping them here would look raggedly narrow
  on a wide screen.
* Blank lines and emoji both survive the paste. Bullet characters (•) and
  ticks (✓) are literal text, not a list format the store understands, so
  they render exactly as typed.

The wording, and every claim in it, is the same as store/listing.md — that
file explains the reasoning and the dashboard settings around them; these
files are the text itself.
